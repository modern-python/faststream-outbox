# Design: Per-repo agent-skill configuration

## Summary

The installed engineering skills (`to-tickets`, `triage`, `to-spec`, `wayfinder`,
`domain-modeling`, `code-review`, `improve-codebase-architecture`) each expect a
per-repo config telling them where issues live, what the triage labels are called,
and which files hold the domain truth. This repo had none, so every skill fell back
to its generic defaults — GitHub-or-markdown guesswork for issues, and the
`.out-of-scope/` + `docs/adr/` homes that this repo deliberately does not have.

Add the three config files under `docs/agents/`, an `## Agent skills` pointer
section in `CLAUDE.md`, and an `exclude_docs` entry keeping the new directory out
of the published site. Docs and config only; no runtime code, no public API.

## Motivation

Two concrete misroutes were available to any skill run in this repo before the
change:

- A rejected alternative would be written to a fresh `.out-of-scope/` directory,
  splitting the corpus that `planning/decisions/` already owns — and the
  prior-rejection check during triage reads that corpus, so a split silently
  weakens it.
- Domain exploration would look for `CONTEXT.md` and `docs/adr/`, find neither,
  and miss `architecture/` — the actual truth home named in `CLAUDE.md`.

Triage had a third failure: only `wontfix` exists on the GitHub repo, so four of
the five canonical role labels would be applied blind.

## Design

`docs/agents/issue-tracker.md` — GitHub via `gh`, with the PRs-as-request-surface
flag off. Two repo-specific sections: the `.out-of-scope/` → `planning/decisions/`
redirect, carrying the frontmatter shape, the mandatory **Revisit trigger**, and
the `just check-planning` gate; and the wayfinder ops, noting the `wayfinder:*`
labels don't exist yet.

`docs/agents/triage-labels.md` — the five canonical roles, label string equal to
role name. `needs-triage`, `needs-info`, `ready-for-agent`, and `ready-for-human`
are created on the GitHub repo as part of this change, so all five now exist and
triage never applies a label blind. The file also records that the repo's
`bug`/`enhancement`/`documentation`/… labels are a separate *kind* vocabulary
triage leaves alone.

`docs/agents/domain.md` — single-context. Read order `CLAUDE.md` →
`architecture/<capability>.md` → `planning/decisions/` → `CONTEXT.md` (absent; the
skills create it lazily). Restates the three-homes split and the same-PR
`architecture/` promotion rule, so a skill does not invent a fourth home, and
carries the `docs/` link rules.

`CLAUDE.md` gains a three-bullet `## Agent skills` section pointing at the files —
the pointer, not the content, so the always-loaded file stays lean.

`mkdocs.yml` gains `exclude_docs: /agents/`. The files sit inside `docs_dir` where
the skills look for them, but they are agent-facing, not user-facing, and
`docs-build` runs `--strict`, which fails orphaned pages.

## Non-goals

- **No `CONTEXT.md`.** The glossary appears when `/domain-modeling` first resolves
  a term; writing one upfront would duplicate `architecture/glossary.md`'s job.
- **No new planning lane or convention change.** This configures the skills to the
  existing convention, it does not alter it.
- **PRs stay out of the triage queue.** The flag is documented and off.

## Testing

- `just docs-build` — clean, and `site/agents/` is absent (the exclusion holds).
- `just check-planning` — `planning: OK`.
- `just lint-ci` — clean.

## Risk

- **Config drift.** If `planning/decisions/`'s frontmatter shape changes, the
  redirect section goes stale and a skill writes an invalid record. Mitigation:
  `just check-planning` fails the PR that does it, and it points at
  `planning/_templates/decision.md` rather than restating the template inline.
  Low impact.
- **Site leak.** A future `exclude_docs` edit could publish the agent docs.
  Mitigation: the entry carries a comment saying why it exists.
